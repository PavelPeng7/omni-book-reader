## What to build

用户改名 EPUB 或完整书籍文件夹、在书库内移动整书，或将完整目录复制到另一 Vault 的受管书库后，仍能识别原有书籍并恢复阅读进度、批注、封面与导出附件。新生成阅读位置链接按固定身份定位当前书籍，避免路径变化导致跳转失效。

覆盖父规格 User Stories：16–19、24–25、36–37。本票只交付上述纵向行为；保留现有未提交工作，不扩大到源码目录重组或旧数据迁移。测试沿用已确认的“书库服务 + 模拟 Vault”边界，断言用户可观察的文件与资料结果；界面继续遵循项目设计规范。

## Acceptance criteria

- [ ] 通过有效每书状态及完整 bookId 发现并定位受管书籍，EPUB 改名、书籍目录改名或库内移动后身份与阅读资料不重建、不丢失。
- [ ] 已打开阅读器能在支持的改名/移动后继续保存到当前有效位置，不向旧路径写入；无法确定新位置时提示并保留状态，不静默建立空书。
- [ ] 复制完整书籍目录到另一模拟 Vault 的受管书库后，可重新发现并打开，恢复进度、批注、书签、统计和受管封面，导出附件仍可解析。
- [ ] 封面与导出采用已建立的相对关联机制；书籍恢复不依赖原 Vault、旧插件缓存或仅存在于内存中的索引。
- [ ] 同一书库重复完整 bookId 沿用冲突保护，不自动选择、合并或重新编号；解除冲突后便携流程恢复正常。
- [ ] 新生成位置链接根据固定书籍身份和 CFI 解析当前位置，当前 Vault 中改名/移动后仍能跳转；新 Vault 生成的链接使用该 Vault 的上下文，不要求改写携带文档中原有的 Vault 专属链接或兼容旧格式链接。
- [ ] 用户说明明确沿用现有文件同步，建议同步完成后切换设备；不宣称支持同书并发进度或批注的自动无损合并。
- [ ] 在书库服务加模拟 Vault 边界覆盖改名、嵌套移动、服务重建、跨 Vault 恢复、资源解析、身份冲突和链接解析；人工检查桌面/移动继续阅读与定位入口。
- [ ] 记录 quick/full 验证及真机检查的实际覆盖，更新身份、便携、协议定位与同步边界文档。
