## What to build

用户在默认 My Reader 书库中显式导入一本 Vault 内的 EPUB，来源文件移动进可识别的独立书籍文件夹；书架仅显示受管书籍，打开、阅读并重启后可恢复同一本书的进度、书签、批注与统计，全局设置随书库保存。这是第一个能演示的受管阅读闭环，不要求先完成所有附属资源或迁移场景。

覆盖父规格 User Stories：1、6–15、33–35、38–40。本票只交付上述纵向行为；保留现有未提交工作，不扩大到源码目录重组或旧数据迁移。测试沿用已确认的“书库服务 + 模拟 Vault”边界，断言用户可观察的文件与资料结果；界面继续遵循项目设计规范。

## Acceptance criteria

- [ ] 首次使用建立默认可见书库；全局设置、每书状态与插件启动信息分离，每书状态带格式版本与完整固定 bookId，索引或缓存不是唯一事实来源。
- [ ] 桌面与移动界面提供显式导入入口；成功后 EPUB 保持原文件名并移动到书名加短 ID 的独立目录，原位置不存在该 EPUB；未导入 EPUB 不进入受管书架、不被静默移动。
- [ ] 书籍文件夹保留可辨认书名，生成目录名少于 100 UTF-8 字节且不覆盖已有内容；同名不同内容至少可独立保存，后续内容去重由独立票完善。
- [ ] 从书架打开受管书籍，修改进度、书签、批注、统计与全局设置，刷新并重建服务后正确恢复；多书资料隔离；保留现有阅读设置、EPUB 安全处理和输入行为。
- [ ] 初始化、移动或状态保存失败时明确提示，来源 EPUB 保留或恢复，不遗留被视为成功的半成品；串行写入和生命周期 flush 不丢最新状态。
- [ ] 损坏或不支持版本的每书 JSON 保留原文并提示，不以空状态覆盖，不阻断其他正常书籍；默认设置不得覆盖损坏的设置文件。
- [ ] 新模式不读取、迁移或自动恢复旧阅读状态，不启动旧导出自动搬迁，不自动清理旧状态、导出及封面缓存；旧 EPUB 仅在显式导入后移动。
- [ ] 保留现有持久化访问方式可用，必要的小范围适配在本票先完成；不得把整个项目的重命名或纯存储层改造拆成无法演示的前置票。
- [ ] 按父规格的书库服务加模拟 Vault 边界验证导入、保存重载、来源移动失败、损坏数据隔离和旧数据不受影响；新入口具备中英文、键盘可达性、可见焦点及窄屏布局。
- [ ] 运行 quick/full 验证并记录结果，更新当前产品行为、架构与执行计划；后续未完成场景不得标为父规格已完成。
