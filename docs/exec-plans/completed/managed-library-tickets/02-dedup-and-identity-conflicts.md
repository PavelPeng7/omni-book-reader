## What to build

用户再次导入内容完全相同的 EPUB 时直接继续已有书籍，原进度与批注不变，重复来源文件留在原位。同名但不同内容可作为新书；同一书库出现多个相同 bookId 的书籍文件夹时，用户得到明确提示，相关书籍暂停写入，移走重复目录后可以恢复。

覆盖父规格 User Stories：21–25、35、38–40。本票只交付上述纵向行为；保留现有未提交工作，不扩大到源码目录重组或旧数据迁移。测试沿用已确认的“书库服务 + 模拟 Vault”边界，断言用户可观察的文件与资料结果；界面继续遵循项目设计规范。

## Acceptance criteria

- [ ] 以 EPUB 完整字节内容识别重复，不以文件名、路径、大小或修改时间单独判定；同内容不同名复用，只有大小或名称相同但内容不同不复用。
- [ ] 重复导入打开现有书籍，保留 bookId、进度、批注、书签与统计，不移动或删除重复来源，不创建额外受管书籍。
- [ ] 同名不同内容分配独立身份及不冲突目录，各自阅读资料互不影响。
- [ ] 发现同一书库多个有效书籍目录拥有相同完整 bookId 时，清楚列出冲突，停止受影响书籍的状态与导出写入；不静默选择、合并、删除或重新编号。
- [ ] 冲突保护作用于书库公开写入入口，后续封面、导出、删除和定位功能复用这一保护，无须单独读取内部索引；非冲突书籍继续可用。
- [ ] 用户移走重复目录后，经正常刷新或重新扫描可恢复唯一身份定位与写入，无须重建资料。
- [ ] 模拟 Vault 集成测试覆盖重启后去重、相同字节不同名、同名异内容、ID 冲突期间零写入以及解除后恢复，断言文件和阅读资料而非摘要算法实现。
- [ ] 桌面/移动端具有中英文结果与冲突提示；记录 quick/full 验证及相应产品和设计更新。
