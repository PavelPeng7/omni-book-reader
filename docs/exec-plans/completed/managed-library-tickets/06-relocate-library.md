## What to build

用户在设置中修改书库位置时，插件整体搬迁全部书籍和全局设置，完成后继续阅读并在重启后使用新位置。非空、非法或重叠目标会被拒绝；搬迁期间的写入与已打开阅读器得到协调，失败时原书库可恢复使用。

覆盖父规格 User Stories：2–5、15、36–40。本票只交付上述纵向行为；保留现有未提交工作，不扩大到源码目录重组或旧数据迁移。测试沿用已确认的“书库服务 + 模拟 Vault”边界，断言用户可观察的文件与资料结果；界面继续遵循项目设计规范。

## Acceptance criteria

- [ ] 设置提供 Vault 内书库路径选项、当前路径与搬迁状态；目标与当前位置相同时无副作用，不将路径修改解释为静默切换到另一非空书库。
- [ ] 拒绝 Vault 外、向上逃逸、与当前书库自我嵌套或会覆盖其他内容的目标；非空目标停止并说明原因，不自动合并或删除目标内容。
- [ ] 成功搬迁包含全局设置和全部完整书籍目录，保留固定身份、相对关联、手写内容及未知用户文件；插件仅在成功后提交新引导位置。
- [ ] 搬迁协调待保存状态、运行中的导入/导出/回收及已打开阅读器，避免搬迁后向旧目录写入；复用统一受管操作边界和已完成的位置重定位，不为每种资源复制一套搬迁逻辑。
- [ ] 失败时原文件与原配置保留或恢复，书库可继续使用，不报告假成功；重启后不会选择半搬迁状态或以空状态覆盖资料。
- [ ] 新位置重启后恢复全部书籍与设置，可继续阅读、导出和正常回收；生成的位置链接依稳定身份定位新位置。
- [ ] 以同一模拟 Vault 边界验证成功搬迁、多书与手写文件保留、非空/非法/重叠目标零副作用、移动及配置提交故障恢复，以及搬迁与待写入交错的结果。
- [ ] 人工检查桌面/移动设置、窄屏、中英文、键盘与焦点；保持 Botanical / Organic Serif 风格并清楚展示进度和失败原因。
- [ ] 记录 quick/full 验证，更新产品行为、架构、设置及执行计划；仅在其他父规格任务均完成并核对验收后，才可宣称整个书库改造完成，本票不得擅自关闭父 Issue。
