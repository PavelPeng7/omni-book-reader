## What to build

用户从书架删除受管书籍时，先看到整个书籍文件夹的删除范围并确认；确认后 EPUB、阅读状态、封面、导出和夹内任意手写文件一同进入 Obsidian 回收机制。取消或失败时，不错误清除阅读资料或让后台写入重新生成已回收目录。

覆盖父规格 User Stories：30–32、38–40。本票只交付上述纵向行为；保留现有未提交工作，不扩大到源码目录重组或旧数据迁移。测试沿用已确认的“书库服务 + 模拟 Vault”边界，断言用户可观察的文件与资料结果；界面继续遵循项目设计规范。

## Acceptance criteria

- [ ] 删除入口明确作用于完整书籍文件夹；确认文案包含 EPUB、进度/批注、封面、导出及用户手写文件，不沿用仅删除 EPUB 的提示。
- [ ] 取消操作不改变任何文件、关联、书架记录或待保存状态。
- [ ] 确认后使用 Obsidian 支持的回收机制处理整个目录，包含嵌套资源和未知用户文件；成功后书架不再展示该受管书籍。
- [ ] 删除前协调该书待写入状态、已打开阅读器及正在执行的受管操作；成功回收后不再向已删除位置写入或重建目录。
- [ ] 回收失败时给出明确提示并保留持久化关联，不先删除唯一状态；不得涉及书籍文件夹外的其他书籍、旧资料或原自定义封面。
- [ ] 按完整书籍身份定位删除对象；若公开书库接口报告身份冲突或失效，不自行猜测目录执行删除。
- [ ] 通过模拟 Vault 集成测试验证包含未来封面/导出形态及任意手写文件的整目录回收、取消零副作用、故障保留和回收后不再写入；用测试夹具提供这些文件即可，不必依赖资源收纳票。
- [ ] 窄屏删除确认、键盘操作、焦点、中英文和至少 44px 触摸目标可用；记录 quick/full 验证及删除范围文档。
