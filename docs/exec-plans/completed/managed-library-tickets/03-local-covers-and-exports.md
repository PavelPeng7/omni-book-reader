## What to build

用户为受管书籍提取或选择封面、生成高亮笔记及章节 Markdown 时，全部资源归入同一个书籍文件夹。自定义封面复制进书籍资料，原图片保留；重复导出继续保留受管块外手写内容，让一本书的资料能够独立备份。

覆盖父规格 User Stories：13、19–20、26–29、34、38–40。本票只交付上述纵向行为；保留现有未提交工作，不扩大到源码目录重组或旧数据迁移。测试沿用已确认的“书库服务 + 模拟 Vault”边界，断言用户可观察的文件与资料结果；界面继续遵循项目设计规范。

## Acceptance criteria

- [ ] 自动提取封面和自定义封面副本均保存在对应书籍文件夹，扩展名匹配真实格式；自定义封面来源图片不移动、不修改。
- [ ] 高亮、笔记和章节 Markdown 及其本地 assets 全部按父规格的每书布局按需生成，不继续在原 EPUB 邻近目录或插件安装缓存写入受管资料。
- [ ] 每书状态中的封面和导出关联、导出本地附件引用可相对于书籍文件夹或当前文档解析，不依赖原 Vault 绝对路径；不额外实现目录移动事件或跨 Vault 发现，这些由便携票交付。
- [ ] JSON 保持批注与进度事实来源；Markdown 单向生成，受管块外手写内容在刷新导出后保留，块内内容由插件维护且界面或说明明确这一点。
- [ ] 损坏或不完整受管标记时保留原文并报告错误，不覆盖用户资料；重复且未变化的导出不产生不必要改写。
- [ ] 新封面/导出不依赖旧缓存或旧导出自动恢复，不自动移动、合并或清理旧文件。
- [ ] 延续现有受管块标识和安全处理；输出路径统一经受管书库解析，未来整库搬迁可通过同一协调边界暂停或等待正在进行的导出。
- [ ] 通过模拟 Vault 的公开封面/导出操作验证资源归属、原自定义封面不变、相对引用有效和写入失败；复用既有批注与章节导出的手写内容及损坏标记回归。
- [ ] 保持桌面/移动端相关入口、中英文、键盘和视觉风格可用；记录 quick/full 验证并更新导出及封面行为文档。
