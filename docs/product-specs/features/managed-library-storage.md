# 受管书库：集中运行时数据与每书独立文件夹

状态：本地实现与自动化验证完成（121 项通过、1 项跳过）；原生验收见 TD-2026-005。原始规格为 GitHub Issue #9。
日期：2026-10-18

## Problem Statement

当前 EPUB 位于 Vault 任意位置，进度与批注集中保存在插件安装目录，封面缓存、高亮笔记和章节导出又分散在不同位置。用户无法通过携带一个书籍文件夹完整备份或移动这本书的阅读资料，也难以明确删除一本书究竟影响哪些文件。

用户需要 Vault 内可见的集中书库，每本书拥有完整独立的资料单元，便于整理、移动、备份和删除。用户明确允许不兼容旧数据。

## Solution

提供可配置的受管书库，默认目录名为 `My Reader`。全局设置保存在书库根目录的 `settings.json`；每本受管书籍使用“书名-短ID”的独立文件夹，收纳保持原文件名的 EPUB、`book.json`、实际格式的封面、高亮文档 `高亮.md`、笔记文档 `笔记.md`，以及 `章节导出` 子目录和其中的 `assets` 资源目录。封面及导出按需生成。

用户显式导入书籍后，EPUB 被移动到书籍文件夹，原位置不再保留。书架仅展示受管书籍。每本书拥有固定书籍身份，改名或移动后仍保留进度与批注；整体复制书籍文件夹到另一 Vault 的书库后，可以继续使用其中的阅读资料。

删除操作在确认范围后，将整个书籍文件夹送入回收站。旧阅读数据不读取、不迁移、不自动清理。Markdown 继续单向导出，并保留受管块外的用户内容。

## User Stories

1. 作为阅读者，我希望默认获得名为 My Reader 的可见书库，以便在 Vault 内找到全部受管阅读资料。
2. 作为阅读者，我希望在设置中修改书库位置，以便适应自己的 Vault 组织习惯。
3. 作为阅读者，我希望修改书库位置时整体搬迁现有书库，以便继续使用已有书籍与设置。
4. 作为阅读者，我希望目标目录已有内容时停止搬迁并提示，以便避免覆盖或意外合并文件。
5. 作为阅读者，我希望搬迁失败后原书库仍可用，以便继续阅读并重试。
6. 作为阅读者，我希望显式导入 Vault 内的 EPUB，以便自行决定哪些文件交给插件管理。
7. 作为阅读者，我希望导入时将 EPUB 移入独立书籍文件夹，以便原位置不再留下同一份原文件。
8. 作为阅读者，我希望插件不会自行搬动全 Vault 的 EPUB，以便维持未导入文件的组织方式。
9. 作为阅读者，我希望导入失败时来源 EPUB 得到保留或恢复，以便不丢失书籍。
10. 作为阅读者，我希望书架只展示受管书籍，以便书架与实际管理范围保持一致。
11. 作为阅读者，我希望书籍文件夹名称包含可辨认的书名与身份后缀，以便人工识别并区分同名书。
12. 作为阅读者，我希望生成目录名满足既有短路径限制，以便避免长书名导致文件操作失败。
13. 作为阅读者，我希望每本书的 EPUB、进度、批注、封面及导出集中存放，以便一次备份就能携带完整资料。
14. 作为阅读者，我希望关闭并重新打开插件后恢复阅读位置、书签、批注及统计，以便连续阅读。
15. 作为阅读者，我希望全局设置随书库保存，以便备份书库时一并保留阅读偏好。
16. 作为阅读者，我希望书籍文件或书籍文件夹改名后保留书籍身份，以便原有资料不因路径变化而丢失。
17. 作为阅读者，我希望在书库内移动完整书籍文件夹后仍能继续阅读，以便按自己的方式整理书库。
18. 作为阅读者，我希望将完整书籍文件夹复制到另一 Vault 的书库后恢复阅读资料，以便跨 Vault 携带书籍。
19. 作为阅读者，我希望封面及导出附件引用在整书移动后仍有效，以便不依赖原 Vault 的绝对位置。
20. 作为阅读者，我希望自定义封面被收纳进书籍文件夹，以便迁移书籍时不依赖外部封面文件。
21. 作为阅读者，我希望重复导入完全相同内容时打开已有书籍，以便不产生重复书籍或重置进度。
22. 作为阅读者，我希望重复导入时来源文件留在原位，以便已有书籍被复用时不意外移动另一个文件。
23. 作为阅读者，我希望同名但内容不同的 EPUB 可以分别收录，以便管理不同版本或不同作品。
24. 作为阅读者，我希望同一书库出现相同书籍 ID 的多个文件夹时收到提示并停止相关写入，以便避免写错资料。
25. 作为阅读者，我希望移走重复身份的文件夹后可恢复正常读写，以便解决冲突后继续使用。
26. 作为阅读者，我希望高亮和笔记按需导出到各自书籍文件夹，以便方便阅读与链接。
27. 作为阅读者，我希望重新导出保留受管块外的手写内容，以便继续积累自己的总结。
28. 作为阅读者，我希望明确知道受管块由插件维护，以便理解块内手动修改可能在下次导出时被覆盖。
29. 作为阅读者，我希望章节 Markdown 与所需本地附件属于同一本书，以便整书携带时保持章节资料完整。
30. 作为阅读者，我希望删除前知道 EPUB、阅读状态、导出及夹内手写文件都会被删除，以便作出明确选择。
31. 作为阅读者，我希望确认删除后整个书籍文件夹进入回收站，以便按书统一清理并有机会从回收站取回资料。
32. 作为阅读者，我希望取消删除后所有文件和阅读资料不变，以便安全退出误操作。
33. 作为阅读者，我希望新格式不会自动恢复旧进度或批注，以便明确地重新开始。
34. 作为阅读者，我希望旧导出、缓存和阅读数据不会被自动清理，以便自行决定如何保留旧资料。
35. 作为阅读者，我希望损坏的状态文件得到提示且不被空数据覆盖，以便保留恢复资料的可能。
36. 作为多设备阅读者，我希望通过现有 Obsidian 文件同步携带书库，以便继续使用已有同步方式。
37. 作为多设备阅读者，我希望清楚了解并发编辑不会自动合并，以便在同步完成后切换设备。
38. 作为移动端阅读者，我希望导入、路径设置和删除确认在窄屏下可用，以便在手机上完成书库管理。
39. 作为键盘用户，我希望新增管理入口具备语义标签、可见焦点和键盘操作，以便独立完成操作。
40. 作为中英文界面用户，我希望管理入口、错误及确认提示遵循所选界面语言，以便理解操作结果。

## Implementation Decisions

- 使用既有领域词汇：书库、书籍文件夹、受管书籍、书籍身份、重复导入。源码模块目录重组不在本次范围。
- 建立统一书库管理服务，协调发现、移动导入、身份定位、内容去重、整书回收和根目录搬迁。优先复用现有 Obsidian Vault 与 FileManager 接口及持久化适配器思路，不另建通用存储框架。
- 插件启动信息与全局设置、每书状态分离：插件安装目录仅保存书库位置等必要引导信息；全局设置属于书库；每书状态属于对应书籍文件夹。可重建索引或缓存不作为唯一事实来源。
- 每书状态包含明确格式版本、完整固定 bookId、书籍元数据、来源文件关联、进度、批注、书签、阅读统计及封面/导出关联。短 ID 仅用于可读目录后缀，不能取代完整身份。
- 持久化和公开书库操作围绕书籍身份工作，路径只表示当前位置；全局状态与每书状态分开保存。复用现有写入串行化、待写入刷新与生命周期保存机制，避免并发写入覆盖较新内存状态。
- 受管书籍通过有效书籍状态识别，不因发现任意 EPUB 就自动纳管。书架停止以全 Vault EPUB 枚举作为受管书籍来源；书库外文件可显式导入，不能通过打开文件触发静默搬动。
- 导入通过 EPUB 内容摘要比较完全相同的字节内容，不以名称、路径、大小或修改时间单独判定重复。摘要算法、摘要缓存与扫描优化属于实现细节；行为必须符合重复复用、同名异内容分离的契约。
- 导入新书时分配稳定身份并移动来源文件。初始化、注册与来源移动须具备失败恢复机制，失败不能被报告为成功，不能留下无法识别的半成品或丢失唯一来源。
- 每书内部关联使用可在移动后解析的相对引用；自定义封面须复制进受管书籍资料，保持其来源图片不受影响，自动提取封面也归属于该书。不得依赖原 Vault 的外部封面或插件安装目录缓存才能恢复整书资料。
- 目录及文件改名、书库内移动后重新定位书籍身份；另一 Vault 的受管书库能通过完整文件夹恢复书籍。新生成阅读位置链接应依据稳定身份定位当前位置；不增加旧格式协议链接兼容要求。
- 书库出现重复完整 bookId 时提示受影响书籍并暂停相关写入；不静默选取一个目录、不自动合并或重新编号。用户消除重复后能重新识别并恢复。
- 生成书籍文件夹名保留可识别书名与短 ID，遵守少于 100 UTF-8 字节的已有约束并避免覆盖。原始 EPUB 名称和用户自定义父目录不适用生成名称截断规则。
- 根目录配置限定于 Vault 内；拒绝会导致书库与自身重叠、覆盖其他文件或逃逸 Vault 的无效目标。对非空目标不自动合并；搬迁成功后再提交新位置，失败须保留或恢复可用原书库。
- 运行态书库搬迁须协调未完成的导入、导出、状态写入及已打开阅读器，避免继续向旧位置写入。具体采用暂停或等待由实现选择，外部行为必须保持一致且失败不丢数据。
- 删除入口在执行前清楚展示整书删除范围，明确包含用户手写文件；取消无副作用，确认后使用 Obsidian 回收机制处理整个书籍文件夹。失败不得提前丢弃唯一的持久化关联。
- 批注与阅读状态 JSON 为事实来源；高亮、笔记和章节继续按现有受管块规则单向生成。保留块外手写内容，标记损坏时保留原文并报告错误，不静默覆盖。导出文件和资源按需创建。
- 旧数据兼容策略为全新开始：不加载、迁移、自动恢复或清理旧阅读状态、旧封面缓存和旧导出。移除旧目录数据恢复与旧导出自动搬迁在新模式中的执行路径；不在启动时移动旧 EPUB。
- 新格式仍须检查数据合法性；损坏或不可识别的状态不能作为空书籍保存并覆盖原文。将错误隔离到相关书籍，尽可能让其他正常书籍继续可用。
- 沿用用户现有文件同步，不提供并发修改自动合并。界面或用户说明应说明同步后切换设备的使用边界，不承诺冲突无损恢复。
- 更新插件生命周期、书架、阅读状态访问、封面管理、批注/章节导出、设置与定位链接相关集成；保持 EPUB 安全处理、阅读输入行为、桌面与移动端支持及既有主题约束。
- 新界面沿用 Botanical / Organic Serif 设计、现有主题变量和图标方式，提供至少 44px 触摸目标、清楚的操作状态、键盘与焦点支持及中英文文案。

## Testing Decisions

- 用户已确认测试边界：以“书库服务 + 模拟 Vault 文件系统”为主要集成边界，通过公开操作验证可观察的文件、数据与错误结果，复用现有导出测试并补充桌面/移动端界面检查。
- 好测试关注导入后实际文件归属、保存并重载后的阅读资料、移动后的身份与引用、取消操作无副作用和失败后资料仍在；不绑定私有方法、内部调用顺序、具体哈希算法或非契约性的缓存结构。
- 优先在同一模拟文件系统中完成导入 → 更新进度及批注 → 刷新写入 → 重建服务 → 恢复 → 改名/移动 → 导出 → 回收的代表性整书流程，减少为每个内部模块重复造测试边界。
- 测试先例是现有持久化内存适配器的重载与串行保存测试，以及批注文档、章节导出的 Map 模拟 Vault 与 FileManager 测试；扩展这些模式支持二进制内容、重命名、回收、重新枚举和故障注入。
- 在主要边界验证：新书导入移动来源；完全相同内容复用且来源不动；同名不同内容独立收录；书架排除未受管 EPUB；固定 ID 跨改名、移动和重新启动稳定。
- 在主要边界验证：完整书籍文件夹复制到新的模拟 Vault 后恢复进度、批注与本地封面/附件；同库重复 ID 阻止相关写入，移除冲突后恢复。
- 在主要边界验证：根目录成功搬迁保留全局设置和全部书籍；非空、非法或重叠目标不产生搬迁；初始化、来源移动、写入与搬迁故障不丢失唯一来源且不提交错误根目录。
- 在主要边界验证：整书回收包含 EPUB、JSON、封面、导出及手写文件；取消或失败不错误删除状态；正常写入和旧位置写入不会在搬迁后交错。
- 复用导出模块现有测试验证受管块外手写内容保留、重复导出行为、章节附件留在书籍管理范围，以及损坏受管标记不覆盖原文。仅在该独立边界已有明确回归价值时保留聚焦用例。
- 在主要边界验证：旧数据及旧导出不会被加载、迁移或清理；异常新状态不会被默认值静默覆盖，其他正常书籍仍可使用。
- 验证全局设置和每书资料分别保存、待写入状态在重载前正确刷新、生成目录名满足 UTF-8 字节限制；多个正常书籍互不串数据。
- 人工在桌面和移动端检查书库设置、导入入口、受管书架、整书删除确认、失败提示、阅读位置定位与书库搬迁后的继续阅读；覆盖窄宽布局、中英文、键盘焦点、减少动态效果设置。
- 实施中运行 `npm run verify:quick`，完成前运行 `npm run verify:full`；记录实际结果及未覆盖的真机边界，不将模拟文件系统测试描述为真实 Obsidian 端到端测试。

## Out of Scope

- 源码按领域重新分文件夹、通用架构重写或引入新的 UI 框架。
- 自动读取、迁移、恢复或清理旧进度、批注、导出及缓存；旧格式位置链接兼容。
- 自动搬动或纳管整个 Vault 的 EPUB，以及 Vault 外文件导入工作流。
- 从手动编辑的 Markdown 反向修改阅读器批注。
- 以语义内容去重不同字节版本的 EPUB，或自动合并不同版本的阅读进度。
- 同库重复身份自动修复、自动合并现有非空书库。
- 云端服务、同步后端、同书多设备并发修改的自动无损合并。
- 将任意手写文件纳入结构化批注，或在整书回收之外提供单独撤销历史系统。

## Further Notes

- 本规格综合五轮已确认的设计决策及用户对测试边界的确认；规格发布后用户授权连续实施，现已完成本地实现与自动化验证。没有对真实用户书籍执行导入或回收。
- 目录命名、相对资源、自定义封面归属和定位链接属于实现整书便携目标的必要约束；具体算法及内部类型由实现者在现有边界内确定。
- 放弃旧数据兼容不改变受管块外手写内容保留原则，也不代表允许自动清理旧文件。
- 工作区已有其他未提交改动，实施应保留它们并以当前有效架构为基线。
- 实施完成时更新当前产品规范、架构、设计、执行计划及必要用户说明，并记录验证结果与已知限制。
