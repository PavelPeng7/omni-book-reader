- 用户允许不兼容旧数据；具体影响范围随重构范围确定。这不构成删除现有文件的授权。
- 首轮已确认：改造运行时数据，包含书籍、批注、进度、封面、导出；目标是统一收纳，以及每本书具有便于整体移动、备份和删除的独立文件夹。
- 源码按模块分目录不属于本轮范围。
- 第二轮已确认：书库位于 Vault 内可见目录，默认 `My Reader/`，可在设置中修改。
- 第二轮已确认：导入 EPUB 时移动到书籍文件夹，原位置不再保留；此处是未来导入行为的设计决定，尚未执行文件移动。
- 第三轮用户以 `ok` 确认全部推荐：固定 bookId；书架仅展示受管书籍、书库外显式导入；同内容重复导入打开已有书籍且来源文件留在原位，同名不同内容作为新书；删除前确认，将含手写文件在内的整个书籍文件夹送入回收站。
- 第四轮用户以 `ok` 确认全部推荐：下述目录布局、修改根目录时整体搬迁且非空目标不合并、Markdown 单向生成并保留受管块外内容、旧数据不读取不迁移不清理。
- 第五轮用户以 `ok` 确认全部推荐：整书目录可改名、在书库内移动及复制至另一 Vault 的书库后恢复；同库重复 bookId 提示冲突并暂停写入；沿用现有文件同步，不实现并发修改自动合并。

## 第二轮结论

- 根目录：Vault 内可见的可配置书库目录，默认 `My Reader/`。
- EPUB 归属：导入时移动到每书文件夹，原位置不再保留。
- 书籍身份：第二轮未答复，第三轮已确认固定 bookId。

## 第三轮结论（全部推荐已确认）

- 书籍身份：固定 bookId，文件或目录改名后仍关联原有资料。
- 收录范围：书架只展示受管书籍；书库外 EPUB 经显式导入后移动，不自动搬动全 Vault 的 EPUB。
- 重复导入：同内容复用现有书籍，保留现有进度与批注且不移动重复来源；同名不同内容作为新书。
- 删除：整本书籍文件夹进入回收站，包含 EPUB、阅读数据、封面、导出及夹内手写内容；操作前明确提示范围并确认。

## 第四轮结论（全部推荐已确认）

- 布局：`My Reader/settings.json` 保存全局设置；每书以 `书名-短ID/` 收纳原名 EPUB、`book.json`、封面、`高亮.md`、`笔记.md` 和 `章节导出/assets`。插件 `data.json` 仅保留书库位置等引导信息；每书目录名继续遵守现有短路径约束。
- 更改根目录：整体移动当前书库；目标非空时拒绝自动合并，保留原目录和配置。
- Markdown：维持单向生成，高亮/笔记的受管块由插件更新，块外手写内容保留；JSON 为批注与进度的事实来源。
- 旧数据：不自动导入、恢复、移动或删除旧阅读数据、导出及缓存；由用户重新导入 EPUB 开始使用新格式。

## 第五轮结论（全部推荐已确认）

- 整书便携：书籍文件夹改名、在书库内移动或复制到另一 Vault 的受管书库后，通过有效的 `book.json` 恢复身份及关联；资源采用书籍文件夹内相对路径。同一书库若发现相同 bookId 的多个文件夹，提示冲突，暂停对冲突书籍写入，等待用户移走重复文件夹。
- 同步范围：依赖 Obsidian/用户现有文件同步，不实现自动合并同一本书的并发批注或进度。推荐单设备完成阅读并同步后切换设备；并发修改可能产生覆盖或同步冲突文件，不承诺无损合并。

## 已确定的实现约束

- 导入失败应保留或恢复来源 EPUB；不得在附属数据初始化失败后留下无法识别的半成品书籍。
- 书库搬迁成功后再更新引导路径；冲突或失败时保留可继续使用的原书库。
- 异常 JSON 不应被默认空数据静默覆盖；受影响书籍应提示错误并保留原文件。
- 导入、整库搬迁和整书删除须覆盖失败路径测试；运行项目 quick/full 验证。
- 这些是保护用户数据的实现要求，不增加旧数据迁移或多设备自动合并范围。
