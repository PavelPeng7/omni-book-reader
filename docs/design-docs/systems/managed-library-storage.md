# 受管书库与每书独立存储

Status: Released in 2.0.0; automated verification passed; native validation tracked in TD-2026-005
Date: 2026-10-18

## 背景与决策

用户希望解决阅读资料散落问题，并能按书整体移动、备份和删除。运行时资料集中在 Vault 内可见、可配置的书库，默认 `My Reader/`。源码目录重组不属于本轮范围。

```text
My Reader/
├─ settings.json
└─ 书名-短ID/
   ├─ 原书名.epub
   ├─ book.json
   ├─ cover.jpg
   ├─ 高亮.md
   ├─ 笔记.md
   └─ 章节导出/
      └─ assets/
```

`settings.json` 保存全局设置；`book.json` 保存书籍身份、元数据、进度、批注、书签及统计。封面示例为 JPEG，实际扩展名应匹配图片格式。插件安装目录内的数据仅保留书库位置等引导信息。按需生成封面及导出文件，不要求无内容时创建空文档。

## 文件归属与操作

- 导入由用户显式触发，将 EPUB 移入独立书籍文件夹，原位置不再保留；书架仅展示受管书籍。
- 固定 bookId 表示书籍身份；路径或名称变化不产生新身份。书名加短 ID 用于可读目录命名，沿用生成目录名少于 100 UTF-8 字节的约束。
- 内容完全相同的 EPUB 重复导入时打开已有书籍，保留已有阅读资料及重复来源文件。同名不同内容作为新书。
- 每书内部资源采用相对路径；改名、书库内移动、整体复制到另一 Vault 的受管书库后，依据有效 `book.json` 恢复身份与资料。
- 同一书库出现重复 bookId 时明确提示并暂停相关书籍写入，待用户移走重复文件夹。
- 删除前明确确认范围，将整个书籍文件夹送入回收站，包含用户放入其中的手写文件。
- 设置中修改根目录时整体搬迁书库。目标目录非空时停止并提示，不自动合并；成功后才更新引导路径。

## 本地安装身份检查

同一 Vault 的插件目录只能有一份 `id: omni-book-reader` 的有效 `manifest.json`。开发目录和旧安装目录并存时，Obsidian 按扫描顺序将清单写入同一 ID 索引，后读到的目录覆盖先读到的目录；`community-plugins.json` 只有 ID，不能据此判断实际加载目录。排查时须检查全部清单，不能只看当前源码的版本。停用重复安装前将其发布资源备份到 Vault 外；旧 `data.json` 和阅读书库不参与清理，也不合并进新格式。

可选只读检查：设置 `OMNI_BOOK_READER_LIBRARY_FIXTURE` 为含 `.obsidian/plugins` 和 `My Reader` 的 Vault 根目录后运行 `npx vitest run tests/managed-library-fixtures.test.ts`。检查安装身份唯一性、全部新格式文档可回读和资源引用存在；不驱动当前运行进程，也不能证明原生弹窗已消失。EPUB 解析另用 `OMNI_BOOK_READER_E2E_VAULT` 指向书库并运行 `tests/epub-fixtures.test.ts`。

## 数据与兼容性

- JSON 是阅读状态及批注的事实来源；Markdown 单向生成，更新受管块并保留块外手写内容。受管块内手动修改可能被下次导出覆盖。
- 允许不兼容旧数据；不读取、迁移、自动恢复或清理旧阅读数据、导出及缓存。用户重新导入 EPUB 后开始使用新格式。
- 依赖既有文件同步，不实现同一本书多设备并发进度/批注合并；并发编辑可能覆盖或产生同步冲突文件。推荐同步完成后切换设备。
- 导入失败须保留或恢复原 EPUB；异常 JSON 须提示并保留原文件，不以默认空数据覆盖。文件初始化与搬迁失败不得留下被当作成功的半成品。

## 取舍

### 明确授权的一次性旧数据迁移

另行明确授权的一次性数据迁移不属于插件启动流程，也不改变运行时不自动读取、恢复或迁移旧数据的契约。迁移脚本、来源备份和个人操作记录保留在本地，不随插件发布。缺少有效 CFI 的历史摘录只作为文档保留，不生成推测位置。

相比继续扫描全 Vault 和集中 `data.json`，受管书库要求先导入书籍，产生更多小文件，但每书资料可以整体携带，且移除插件时不再将阅读资料和插件安装目录绑定。相比自动迁移旧状态，本方案采用全新格式，降低兼容分支成本，代价是旧进度和批注不会自动延续。

## 验证与实施状态

### 初始化失败的恢复边界

`ReaderDataStore.isLoaded` 区分默认的未加载界面状态与成功读取的持久状态。首次读取失败时保存原始异常，定时 persist 不提交默认数据，flush 返回原始加载错误。Vault 事件不向失败的 store 填充 discover 结果，避免“书架有书，但书库一直不能写”的半初始化状态。

插件首次尝试失败后，在 `onLayoutReady` 再试一次；不在 `onload` 中等待布局，以免阻塞布局本身。手动刷新也先尝试完整初始化，成功后才恢复通常的 flush/discover 流程、设置与已恢复阅读页。同一时刻的恢复请求共享加载 Promise；卸载后不启动延迟恢复。持续故障仍保留文件并报告原始错误，不将 ready 强设为成功。书库仅在 discover 完成后设为 ready；重试会清除上次初始化的诊断标志，重新校验文件。

本机原生会话曾实际出现 ready=false、settingsRaw=null 而后续 discover 得到 24 本书；完整初始化重试成功。索引尚未就绪可以在模拟 Vault 中复现同一保护错误链，但首次原始异常在旧实现里未保留，因此不能断言本机首次失败一定由索引时序引起。失败日志现在保留在控制台。

### 受管书库实施

`ManagedLibrary` 已接入插件生命周期、书架、阅读器导出与设置。`ReaderDataStore` 保留路径索引的运行时门面，在存储边界转换为固定身份与每书文档；`reconcile` 保持已打开阅读器的状态对象引用，同时更新当前位置。每书文档与设置的落盘格式均为 version 1，内存 ReaderData 的旧 schema 编号不代表继续加载旧文件。

安装目录使用独立 `library-location.json`，不覆盖旧 `data.json`。全局设置与每书状态通过 Vault API 写入；内容摘要使用当前 EPUB 字节的 SHA-256，不信任过时缓存作为去重证据。自定义封面复制为 custom-cover 加实际扩展名；提取封面使用 cover 加实际扩展名。

所有受管文件变更共享串行队列。状态更新使用 Vault.process 核对预期原文，外部修改或损坏文档会暂停覆盖，用户检查文件并重载插件后读取外部版本；不自动丢弃未保存内存状态以换取刷新成功。书库事件进行位置重映射与延迟重新发现。已删除书籍不会被队列里的旧快照重新创建。

文库刷新根据可见书籍状态、源文件/自定义封面签名及文库显示设置判断是否需要重建页面；Vault 事件、工作区焦点变化或重复发现本身不是重建依据。可见模型未变时保留已加载封面、搜索输入与滚动位置，避免重新播放封面骨架和淡入动画。搜索在现有列表上更新；实际模型改变时沿用当前搜索词重新渲染，并清理旧封面的可见性观察。显式封面失效和视图关闭会清空渲染签名。此处仍对实际数据变化执行完整重绘，未引入增量 DOM 框架。

搬迁先记录 pendingRoot，再执行目录重命名，成功后提交 root 并清理 pendingRoot；启动时先检查源/目标实际存在情况再建立目录，以恢复改名后未提交位置的中断。原路径和目标路径互相包含时拒绝搬迁；已有空目标通过 Obsidian 回收后接收书库，非空目标保留并拒绝合并。失败时尝试回滚；若回滚也失败，提示资料实际所在新路径并保留启动恢复记录。

批注由库内文档服务写入书籍目录；章节导出与单图保存也经队列执行，章节正文中的内嵌图片使用相对 assets 链接。新 CFI 链接包含 bookId 与当前 Vault 上下文；跨 Vault 携带文档中的既有 Vault 专属链接不会被批量改写，重新导出可生成当前 Vault 的链接。

模拟 Vault 集成测试已覆盖 23 个代表性流程：导入与重载、去重、源文件恢复、身份冲突、外部/损坏数据保护、封面副本、Markdown 手写保留、内嵌图片与相对附件、改名/库内移动、跨 Vault 恢复、整书回收及失败、搬迁及失败回滚、启动恢复与操作队列交错。quick/full 检查均已通过（121 项测试通过、1 项既有 fixture 跳过），生产构建和资源验证通过。当前环境没有可驱动的原生 Obsidian 桌面/移动会话，未将模拟测试视为真机验证。
